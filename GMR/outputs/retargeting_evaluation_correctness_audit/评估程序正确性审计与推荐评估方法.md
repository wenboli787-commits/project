# 重定向评估程序正确性审计与推荐评估方法

审计日期：2026-07-15  
执行环境：Ubuntu 22.04 / WSL2，Python 3.10.12，NumPy 2.2.6，MuJoCo 3.10.0，PyTorch 2.13.0+cpu  
审计输入：9 个参考 NPZ；Direct Mapping、Basic IK、GMR 各 9 个 PKL；`g1_mocap_29dof.xml`

## 1. 最终结论

当前评估程序可以稳定完成文件配对、时间重采样、MuJoCo 前向运动学和报表输出，但**当前总排名不能视为正确结论**。问题不是 PKL 没有读到，也不是 Ubuntu 与 Windows 的计算差异，而是若干核心指标的物理含义与实现口径不一致。

最重要的结论如下：

1. **你指出的 Direct Mapping“穿模 100%”已被独立复现。**对 `group=1` 视觉网格逐帧计算有符号距离，并排除直接父子链节后，Direct 的 9 个动作均为 100% 帧存在超过 1 mm 的网格相交。
2. 当前程序报告的并不是“视觉穿模率”，而是 MuJoCo 已生成的碰撞代理体 `data.contact`。Direct 的这个代理指标宏平均只有 29.525%，所以指标名称和用户肉眼观察不一致。
3. XML 中有 35 个视觉专用几何体，其 `contype=0, conaffinity=0`；左右 `rubber_hand` 都没有碰撞几何体。视觉网格发生穿模时，这些部位不会进入 `data.contact`，当前程序必然漏报。
4. **Basic IK 的 100% 关节越限基本正确。**即使把容差提高到 5°，9 个动作的越限帧比例仍是 100%；单帧最大超限达到 1157.397°。这不是浮点误差，而是文件本身标记的 `unconstrained_ik` 结果真实大幅越界。
5. **GMR 原报告中的非零越限是错误的。**零容差下宏平均为 0.207%，但最大“越限”只有约 `6.4e-15°`；容差设为 0.01° 后立即变为 0%。
6. **当前脚滑指标不具备决策安全性。**脚已经深入地面超过 5 mm 时，仍会被当作有效接触。被错误计入接触的足部样本宏平均为 Direct 22.005%、Basic IK 50.115%、GMR 63.256%。因此原报告中“GMR 脚滑最低”不能直接解释为最好。
7. 地面穿透的几何重算与 MuJoCo 地面接触一致；问题主要在于报告没有把严重穿地作为脚滑指标的有效性前提。超过 5 mm 穿地的帧比例宏平均分别为 Direct 42.481%、Basic IK 81.179%、GMR 92.856%。
8. 参考人体尺度取自“前 30 个有姿态帧的所有关节最高点减最低点”，因此同一个 SMPL-X 体型会因动作不同得到不同尺度。例如 `113_20` 与 `113_21` 的 gender 和 betas 完全相同，但当前尺度分别为 0.761215 与 0.767753。
9. Root-relative MPJPE 把 pelvis/root 也放进 15 个点求平均；根节点在去根之后误差恒为 0，所以报告值被固定压低 `1/15 = 6.67%`。
10. `self_collision_event_count` 统计的是“碰撞体对从无到有的次数”，不是碰撞帧数，也没有按动作时长归一化；它不能直接用来跨时长比较。

## 2. Direct Mapping 为什么会出现“肉眼 100%，程序约 30%”

这两个数字来自不同定义，不能混用。

| 定义 | Direct 宏平均 | 含义 |
|---|---:|---|
| 当前碰撞代理体 contact 帧比例 | 29.525% | 只统计 MuJoCo 允许碰撞且实际生成的 `data.contact`，排除直接父子链节 |
| 视觉网格非父子相交率，深度 > 1 mm | 100.000% | 与用户看到的“模型表面穿模”更接近，但会包含模型设计中长期重叠的二阶相邻链节 |
| 视觉网格非局部相交率，深度 > 1 mm | 27.360% | 再排除运动学图距离不超过 2 的近邻链节，以及 XML 中立姿态已经相交的体对 |

因此，Direct 的视觉穿模 100% 是可复现事实，但这个数字包含一部分机器人网格本身在中立姿态就存在的近邻重叠。若要公平比较三种重定向方法，不能只使用一个模糊的“自碰撞”数字，至少应同时报告：

- **视觉网格相交率**：回答“渲染画面里是否穿模”；
- **非局部视觉相交率**：排除固定近邻和中立姿态已有的结构性重叠；
- **碰撞代理体物理接触率**：回答 MuJoCo 碰撞模型是否发生物理自碰撞；
- 每种定义的最大穿透深度、碰撞帧比例和最常见体对。

只有把名称和排除规则写清楚，100% 与 29.5% 才不会被误认为同一个结论。

## 3. 各指标正确性判定

| 指标 | 判定 | 主要原因 | 是否可用于当前排名 |
|---|---|---|---|
| 输入配对、FPS、共同时间区间 | 通过 | 9 组动作完整配对；独立清点一致 | 可以 |
| 根轨迹误差 | 基本可计算 | 首帧 XY/yaw 对齐后比较全局轨迹；需明确它衡量轨迹复现而非单帧姿态 | 有条件可以 |
| Root-relative MPJPE | 有定义偏差 | 包含恒为 0 的 root；关键点位置也是身体原点而非统一解剖标志 | 修正后使用 |
| 末端误差 | 有映射偏差 | SMPL-X wrist 对机器人 rubber hand，参考点和机器人点不是同一解剖位置 | 修正或标注后使用 |
| 关节限位 | 部分正确 | Basic IK/Direct 真实越限；GMR 被零容差浮点误报 | 加容差后使用 |
| 地面穿透 | 数值通过 | 地面为 z=0；足底球最低点与 MuJoCo 地面接触一致 | 可以，但需同时报告比例和深度 |
| 脚滑 | 不通过 | 没有接触高度下界；严重穿地仍被计为接触；低滑动可能只是有效接触太少 | 当前不可排名 |
| 自碰撞 | 不通过“视觉穿模”含义 | 只看碰撞代理体 contact，遗漏视觉专用网格和 rubber hand | 必须拆分指标 |
| 平滑性/jerk | 可计算但需保护 | Basic IK 的极端值与角度跳变一致；应检查角度连续性和滤波边界 | 有条件可以 |
| 汇总与排名 | 不通过 | 所有数值列统一按“越小越好”排名；碰撞事件未按时长归一；宏平均口径未在标题中说明 | 当前不可作为最终总排名 |

## 4. 推荐的公平评估流程

### 4.1 数据与配对

1. 用动作 ID 做一对一配对，每个动作必须同时存在参考、Direct、Basic IK、GMR 四份数据。
2. 记录原始 FPS、帧数和时长；在四者共同覆盖的时间区间内重采样到同一时间轴。
3. 根四元数使用球面插值；有限转动关节需要先检查角度连续性，再进行插值。
4. 每个动作输出独立结果；任何缺失、NaN、异常跳变都必须标记，不能静默丢弃。

### 4.2 尺度和坐标

1. 统一右手系、前向轴和上轴。
2. 参考人体尺度应由相同 betas 的 SMPL-X **零姿态**计算，不能取动作前 30 帧的最高/最低关节。
3. 若姿态误差使用关节点，应优先采用零姿态关节高度；若比较外表或网格，应采用零姿态顶点身高。两者不能混用。
4. 机器人高度也必须使用与参考一致的定义。例如参考用足底，则机器人不能用足部几何中心；应使用足底支撑点。
5. 同一个 SMPL-X 体型在不同动作中必须得到完全相同的缩放系数，这是尺度实现的基本单元测试。

### 4.3 姿态保真度

建议同时报告三组指标：

- **全局根轨迹**：首帧对齐后的 root XY、root 高度、yaw 误差；
- **去根局部姿态**：去除根平移和根 yaw 后，计算 14 个非 root 关键点 MPJPE；
- **末端误差**：左右手、左右足分别报告，并保证参考点与机器人点具有一致的解剖含义。

Root-relative MPJPE 不应把恒为 0 的 root 放入均值。若必须保留，应把名称写为“15 点含 root MPJPE”，并同时提供“14 点不含 root MPJPE”。

### 4.4 关节限位

对每个有限关节计算：

```text
excess = max(lower - q, q - upper, 0)
```

建议使用至少 `max(1e-6 rad, 0.01°)` 的数值容差；报告：

- 任一关节越限的帧比例；
- 关节-帧样本越限比例；
- 最大、均值、P95 超限角度；
- 违规最多的关节。

本数据中 Basic IK 即使阈值为 5°仍是 100%，所以它的结论不会因合理容差而改变；GMR 的非零值则会被正确清零。

### 4.5 地面穿透与接触有效性

对足部每个碰撞几何体计算最低支撑点，地面穿透深度为：

```text
penetration = max(ground_z - min_foot_z, 0)
```

同时报告：

- 深度 > 0、> 5 mm、> 20 mm 的帧比例；
- 平均、P95、最大穿透深度；
- 左右足分别的最大深度。

有效接触必须同时满足：

```text
-5 mm <= min_foot_z - ground_z <= 20~40 mm
abs(vertical_velocity) <= 0.10~0.15 m/s
```

更可靠的版本还应结合 MuJoCo 足-地 contact 或接触力。低于 -5 mm 的严重穿地样本不能作为正常支撑接触计算脚滑。

### 4.6 脚滑

脚滑只在相邻两帧都属于**有效接触**时累积水平位移：

```text
sliding_distance = sum(||foot_xy[t+1] - foot_xy[t]||)
sliding_rate = sliding_distance / valid_duration
```

必须与下列保护指标一起报告：

- 有效接触覆盖率；
- 严重穿地但被判接触的比例，目标必须为 0；
- 左右足滑动距离；
- 按总动作时长的 cm/s，以及按有效接触时长的 cm/s。

如果有效接触覆盖率过低，则脚滑指标应标记为不可用，而不是把 0 或很小的滑动当成优秀结果。

### 4.7 自碰撞与视觉穿模

推荐拆成两个正式指标族：

1. **Physics collision**：使用碰撞代理体，按明确的 body exclusion 列表排除直接相邻和设计允许接触；使用至少 1 mm 容差；报告碰撞帧比例、碰撞体对数、最大深度和事件率（次/秒）。
2. **Visual mesh penetration**：使用视觉网格的有符号距离；单独报告所有非父子相交和“排除图距离 <=2、排除中立姿态相交体对”的非局部相交。

左右 rubber hand 必须增加合理的碰撞代理体，或者在报告中明确声明手部不参与 physics collision 指标。否则手穿过躯干时物理碰撞指标会漏检。

### 4.8 平滑性

在共同 30 Hz 时间轴上计算角速度、角加速度和 jerk。计算前应：

- 对允许连续旋转的角度进行 unwrap；
- 有限关节不应通过 `2π` 跳变掩盖越限；
- 说明 Savitzky-Golay 窗口和阶数；
- 单独检查滤波器边界帧；
- 报告均值、P95、最大值和最差关节。

### 4.9 汇总和排序

建议同时提供：

- **动作宏平均**：每个动作权重相同；
- **帧微平均**：每帧权重相同；
- 中位数、P95、标准差或 bootstrap 置信区间；
- 计数指标按秒归一化。

不能把所有数值列都默认设为“越小越好”。例如有效接触覆盖率不是越小越好，reference scale 也没有统一的优劣方向。只有经过方向定义的决策指标才能参与排名。

## 6. 当前结果应怎样使用

- 可以保留：文件完整性、FPS/时长、根轨迹的原始误差、地面穿透深度、Basic IK 的严重关节越限结论。
- 需要重算：GMR 关节越限、MPJPE（不含 root）、尺度归一化、脚滑、视觉穿模、物理自碰撞事件率。
- 暂停使用：当前 overall rank、以 `self_collision_event_count` 直接比较三种方法的结论、以当前脚滑值宣布某方法最好。
- 修复后必须重新执行全部 9 个动作，而不是只覆盖单个样例。

## 8. 修复验收标准

评估程序修改后，至少应通过以下验收：

1. GMR 的浮点边界样本在合理容差下为 0 越限；Basic IK 在 5° 阈值下仍为 100%。
2. 报告明确区分视觉网格穿模与碰撞代理体自碰撞；Direct 的视觉非父子相交率能复现 100%。
3. 左右手碰撞覆盖状态被记录，不能静默缺失。
4. 脚滑的有效接触定义具有上下界；严重穿地计入接触的比例为 0。
5. 每个脚滑结果旁边显示有效接触覆盖率；覆盖率不足时不参与排名。
6. 相同 betas 的不同动作得到相同尺度。
7. 主 MPJPE 不包含恒为 0 的 root，或在名称中明确标注。
8. 碰撞事件以次/秒报告，同时保留碰撞帧比例。
9. 只有方向定义明确的指标参与排名，并在报告中展示宏平均、分布和不确定性。
